# MOGS WebAR

سایت استاتیک با **A-Frame 1.6.0** و **AR.js 3.4.8** برای مدل `MW35018A` و مارکر اختصاصی فایل پروژه.

## اجرا

```sh
cd /Users/m.reza/Desktop/WebAR/marker-viewer
npm run dev
```

روی همین کامپیوتر: http://localhost:8080 . روی گوشی باید از HTTPS معتبر استفاده کنید؛ آدرس HTTP شبکهٔ محلی مجوز دوربین نمی‌گیرد. پوشهٔ `dist` آمادهٔ قرارگیری روی هر میزبان استاتیک HTTPS است. همهٔ فایل‌های کتابخانه، کالیبراسیون، مدل و مارکر محلی هستند؛ CDN در زمان اجرا لازم نیست.

صفحه بدون دکمهٔ شروع، دوربین پشت را با `facingMode: environment` درخواست می‌کند. پذیرش مجوز دوربین توسط کاربر الزامی است. اگر مرورگر پخش خودکار را متوقف کند، دکمهٔ فعال‌کردن دوربین ظاهر می‌شود. تشخیص مارکر و پردازش تصویر در خود مرورگر انجام می‌شود.

## فایل‌ها و تنظیم‌ها

- `dist/index.html`: صحنه، نورپردازی، مسیر مدل و مارکر؛ `patternRatio: 0.77` مطابق تصویر اصلی ۵۱۲×۵۱۲ با کادر قرمز. این مقدار با تنظیم سازندهٔ مارکر تأیید شده است.
- `dist/app.js`: شروع خودکار، وضعیت دوربین، خطاها، تنظیم موقعیت مدل، اندازه و چرخش.
- `dist/assets/model/`: نسخهٔ بدون تغییر فایل‌های glTF و BIN اصلی؛ رنگ زرد از متریال خود فایل می‌آید.
- `dist/assets/marker/pattern.patt`: فایل مارکر اولیه، بدون تغییر، برای نگهداری سابقه.
- `dist/assets/marker/mogs-white-background.patt`: الگوی فعال، از ناحیهٔ داخلی تصویر اصلی با زمینهٔ سفید، در چهار جهت و ترتیب کانال BGR بازسازی شده است.
- `dist/assets/marker/marker-original.png`: تصویر اصلی مارکر ارسال‌شده توسط کاربر، بدون تغییر.
- `dist/assets/brand/mogs-logo.png`: لوگوی ارسالی، بدون تغییر، برای سربرگ و آیکون سایت.
- `dist/marker.html`: نمایش و چاپ تصویر اصلی مارکر با کادر قرمز و حاشیهٔ سفید.

قطر مدل در حالت پیش‌فرض ۱٫۲۵ برابر ضلع خارجی مارکر است؛ این نمایش مقیاس واقعی فیزیکی نیست. محور دیسک از X به Y چرخانده شده و پایین هندسه روی سطح مارکر قرار می‌گیرد. کنترل‌ها اندازه را بین ۲۵٪ و ۳۰۰٪ تغییر می‌دهند. دکمهٔ چرخش در گام‌های ۴۵ درجه و ژست‌ها به‌صورت پیوسته عمل می‌کنند. هنگام قطع تشخیص، مهلت انتخاب‌شده در بخش پایین اعمال می‌شود.

## اصلاح تطابق مارکر

تصویر اصلی بعداً ارائه شد: pattern ratio برابر ۰٫۷۷، اندازهٔ خروجی ۵۱۲ پیکسل و کادر قرمز. فایل pattern اولیه برای نواحی شفاف لوگو RGB صفر ذخیره کرده بود، اما تصویر واقعی زمینهٔ سفید دارد؛ بنابراین الگو از تصویر نهایی بازسازی شد. ابزار تولید مجدد: `tests/marker-calibration.html` (فقط ابزار توسعه، خارج از `dist`).

## نسخهٔ فعال با کادر مشکی

تصویر فعال چاپ و راهنما اکنون `dist/assets/marker/marker-black.svg` است. این SVG کادر را مشکی می‌کند و همان ناحیهٔ داخلی تصویر اصلی را بدون تغییر نگه می‌دارد؛ نسبت ۰٫۷۷ و فایل الگوی اصلاح‌شده ثابت مانده‌اند. نسخهٔ قرمز و فایل‌های اولیه حفظ شده‌اند. نسخهٔ کامل پیش از تغییر در `backups/before-black-marker.zip` موجود است.

`/` مدل اصلی را نمایش می‌دهد. `/mogs-test/` تست جداگانهٔ همین مارکر مشکی با باکس است. `/hiro-test/` تست Hiro است؛ هم‌ترازی ویدئو و بوم در آن با اندازهٔ واقعی دوربین هماهنگ شده است. این اصلاح جایگزین کالیبراسیون دوربین نیست.

آزمون مرورگر: فایل واقعی marker-black.svg از طریق ورودی ویدئوی مصنوعی به AR.js داده شد، تشخیص موفق بود و مدل اصلی نمایش داده شد. خطای جاوااسکریپت ثبت نشد. تست فیزیکی با تصویر جدید هنوز نیاز به اجرای کاربر دارد.

## مهلت قطع تشخیص

مدل پس از اولین شناسایی، هنگام گم‌شدن کوتاه مارکر تا ۱٫۵ ثانیه در آخرین وضعیتِ نسبت به دوربین باقی می‌ماند. این نگه‌داشتن آخرین pose است؛ با برگشت مارکر وضعیت به‌روز می‌شود. اگر مهلت تمام شود، مدل مخفی می‌شود و تا شناسایی تازه برنمی‌گردد. گزینهٔ «مهلت قطع تشخیص مارکر» روی کارت قطعه مقادیر ۰، ۰٫۵، ۱٫۵ و ۳ ثانیه دارد و انتخاب در مرورگر ذخیره می‌شود. منطق در `dist/marker-persistence.js` است. نمایش مدل از والد مارکر جدا شده تا مخفی‌شدن خودکار AR.js باعث چشمک‌زدن نشود. `backups/before-marker-hold.zip` نسخهٔ قبل از این تغییر است.

## اصلاحات موبایل v2

مدل فعال `MW35018A.glb` است؛ دادهٔ هندسه و متریال عیناً از glTF/BIN اصلی آمده ولی دانلود BIN جدا لازم نیست. `model-loader.js` وضعیت HTTP و سربرگ باینری GLB را بررسی می‌کند و پیام متناسب می‌دهد. لایهٔ دوربین در `#ar-stage` جدا و بریده می‌شود تا اندازه‌های داخلی AR.js صفحه را بزرگ نکنند. بستهٔ سرور جدید `WebAR-server-ready-v2.zip` است. اسکریپت بازتولید بسته: `python3 scripts/package-server.py`. گزارش: `MOBILE_FIXES_V2.md`.

## کنترل لمسی مدل v4

روی تصویر دوربین، بعد از نمایش مدل:

- کشیدن افقی با یک انگشت: چرخش حول محور عمودی مارکر (نیم درجه به‌ازای هر پیکسل).
- باز و بسته‌کردن دو انگشت: تغییر اندازه از ۲۵٪ تا ۳۰۰٪.
- پیچاندن دو انگشت: چرخش پیوسته حول همان محور.
- بازنشانی: اندازهٔ ۱۰۰٪ و چرخش صفر.

منطق Pointer Events در `dist/model-gestures.js` است. تبدیل‌ها روی `model-controls` اعمال می‌شوند و با وضعیت ردیابی تداخل ندارند. ژست فقط هنگام نمایش مدل (از جمله مهلت قطع تشخیص) فعال است؛ بازشدن راهنما، قطع ردیابی، لغو اشاره‌گر و خروج صفحه ژست را قطع می‌کند. `touch-action: none` فقط روی لایهٔ دوربین اعمال شده تا pinch مدل صفحه را بزرگ نکند. دکمه‌ها مستقل باقی مانده‌اند.

بررسی‌ها: `npm run check` و `npm run test:gestures`. تست یکپارچه با ویدئوی مصنوعی: `python3 tests/prepare.py`، سرو پروژه روی پورت ۸۰۸۱ و بازکردن `/test-results/?gestures=1`. این تست، ورودی مصنوعی Pointer Events را روی مدل واقعی اعمال می‌کند؛ تست چندلمسی فیزیکی گوشی همچنان لازم است.

برای IIS، اگر مخزن در `C:\inetpub\wwwroot\AR` کلون شده، Physical Path برابر `C:\inetpub\wwwroot\AR\dist` باشد. پس از `git pull --ff-only origin main`، صفحه باید `app.js?v=gestures-v4` و `model-gestures.js?v=gestures-v4` را درخواست کند. اسکریپت بسته‌بندی اکنون `WebAR-server-ready-v4.zip` را می‌سازد و نسخه‌های قبلی را نگه می‌دارد.
